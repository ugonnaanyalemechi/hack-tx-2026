## How to wire a screen

1. Pick a row above whose backend route exists. Run the stack: `docker compose up --build` (db, api on :8000, web on :3000; migrations and seed users run on api start). For the frontend alone against a backend you started yourself: `cd web && npm install && NEXT_PUBLIC_API_MODE=live API_PROXY_TARGET=http://localhost:8000 npm run dev`.
2. Flip the mode. Whole app: `NEXT_PUBLIC_API_MODE=live` (compose: `WEB_API_MODE=live docker compose up --build`). One page load: append `?api=live` to the URL. `NEXT_PUBLIC_*` values are inlined at build time, so rebuild after changing them (the compose dev image reads them at runtime). Requests go to `/api/*`, which Next rewrites to the API; the role switcher's user becomes the `X-User-Id` header.
3. Implement the method in `lib/api/live.ts`. Add one SDK-style method per endpoint using the `get` / `post` helpers (never a raw `fetch(path)` in a component). Methods that still reject with `RuntimeNotAvailableError` are the ones to replace; chat calls live in `createLiveRuntime` in `lib/api/runtime-seams.ts` instead.
4. Delete the `RUNTIME-PLACEHOLDER(#n)` marker on the method you replaced, and update the shapes in `lib/contracts/*` to the backend's real models. Keep the mock binding: Playwright runs on it.
5. Check the row's spec still passes on the mock, then click through the screen with `?api=live` and compare with the screenshot in `tests/__screenshots__/`.

Run a spec: `cd web && PLAYWRIGHT_PORT=3222 npx playwright test --workers=1 tests/<spec>.ts`. Mock test hooks: `?mock=loading|empty|error` (plus `decide-error` for connector decisions).
